# الـSeed والمدة — 2.3.1

الـSeed عدد صحيح يحدد الضوضاء الابتدائية، مش درجة جودة. القيمة 1.25 غير صحيحة؛ 42 افتراضي ثابت لتكرار التجربة، وأي قيمة صحيحة محفوظة يختارها المستخدم تفضل زي ما هي. نفس الـSeed لا يضمن نفس النتيجة لو المقاس أو البرومبت أو الموديل أو الريفرنسات أو طريقة الحساب اتغيرت.

- مشروع أو مسودة قديمة فيها Seed كسري أو خارج النطاق: الواجهة تصلحه إلى 42 وتعرض رسالة واضحة. القيم الكسرية المكتوبة بعد كده تتوقف قبل الرفع والتوليد.
- خانة فارغة أو -1: اختيار عشوائي مرة واحدة قبل بناء البرومبت والجراف. الرقم الفعلي يظهر ويتحفظ، عشان تقدر تعيد التجربة.
- نطاق ComfyUI الأصلي 0–18446744073709551615 محفوظ بدقة، حتى لما الرقم يتعدى دقة أرقام JavaScript. الـbackend يحوله لعدد صحيح دقيق قبل الإرسال. الزيادة في Refine تلتف إلى 0 عند أقصى رقم.
- نفس قواعد التحقق بتشتغل في H3 Video وQwen Image Create/Edit. ما فيش اختيار تلقائي لـSeed «أفضل جودة».

## المدة

كان فيه حد 5 ثواني في الواجهة وتحضير البرومبت، مع إن نود H3 الرسمي بيسمح من 5 فريمات. اتشال الحد المصطنع من Text وFrames وReferences وتحضير البرومبت وتخطيط مصدر ControlNet.

المدة المطلوبة 0.2–15.1 ثانية تتحول لأقرب عدد فريمات صالح: 5+17k عند 24fps، لحد 362 فريم. الواجهة بتعرض المدة الحقيقية قبل الإنتاج: 3 ثواني = 73 فريم ≈ 3.042 ثانية، و1 ثانية = 22 فريم ≈ 0.917 ثانية. الحد الأدنى 5 فريمات ≈ 0.208 ثانية.

المدد تحت 124 فريم ≈ 5.167 ثانية خارج نطاق التدريب المعتاد المكتوب في [نود ComfyUI الرسمي المثبت](https://github.com/Comfy-Org/ComfyUI/blob/3b4c0b0e457cf0a51cf3038e0a6750d8f96ce251/comfy_extras/nodes_minimax_h3.py). مسموحة في الجراف، وجودة الرندر القصير نفسه لسه غير مختبرة على GPU في الإصلاح ده. دعم النود مش ضمان للالتزام بالحركة أو الصوت.

الحدود الفعلية منفصلة: فيديو الريفرنس عند التريم يحتاج على الأقل ثانيتين؛ الاستكمال يحتفظ بـ39 فريم سياق، فلازم الهدف يزيد عنه (أول هدف صالح 56 فريم). ما اتلغتش الحدود دي عشان ما نكوّنش جراف غير صحيح.

## التحقق والترقية

331 اختبار Python و148 اختبار JavaScript نجحوا. اختبار متصفح باستخدام API محلي حقيقي للمشاريع والأصول ضغط Generate في الأوضاع الثلاثة والتقط الجراف قبل إرسال أي رندر GPU، وراجع حفظ وإعادة فتح Seed كبير، العشوائي، إصلاح المسودات القديمة، وحد المدة الأدنى. ده دليل على التوصيل والتحقق؛ مش دليل على جودة توليد GPU للمدد الجديدة.

اللانشر بيسحب تحديثات main حسب سياسته الحالية. التثبيت ينتظر انتهاء الرندر وعمليات التحضير والتصدير، ويحافظ على المشاريع والأصول. الرجوع يتم باستعادة نسخة runtime الاحتياطية أو تثبيت الإصدار السابق مع `--no-update`؛ راجع [دليل الترقية والرجوع](V2_UPGRADE_AR.md).
