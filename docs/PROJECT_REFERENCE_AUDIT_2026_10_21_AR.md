## الأدلة

- 225 اختبار JavaScript ناجحًا، مع مراجعة مستقلة للكود. تشمل اختبارات جديدة عزل الأسماء، تحديث الصفحة، حفظ المسودة، حدود الكاش، إعادة المحاولة، ترتيب المدخلات، وتنظيف الاستعادة المتأخرة. اختبارات Open أثناء الانشغال تتحقق من بقاء المهمة ومدخلاتها، ومن اختيار سيرفر صحيح حتى عندما يختلف عنوان الواجهة عن API وتوجد إعدادات قديمة لسيرفر آخر.
- API داخل السيرفر: قائمة المشاريع 15 ms تقريبًا، مشروع الاختبار 3 ms، مشروع ASAS ذو 34 لقطة 479 ms وحجم JSON نحو 1,298,603 بايت. الأرقام لقطة قياس واحدة وليست ضمانًا.
- تنزيل صورتين من الرابط العام، بإجمالي 10,081,761 بايت: أول وصول 3,637 ms وأربعة طلبات؛ التكرار داخل نفس controller نحو 0.12 ms وبدون طلب شبكة. هذا قياس جلب الأصول، وليس قياس فتح المشروع كله.
- تحقق تطابق ملفات JavaScript الخمسة المنشورة مع المصدر عبر API المحلي والرابط العام. لا توجد نسخة gzip قديمة تقدم بدل المصدر.
- اختبار متصفح حي: Refresh يحفظ Projects ثم Elements؛ Open للمشروع الحالي يعرض Production مع المراجع؛ تغيير اسم المرجع ثم إعادته لا يغير أسماء الكتالوج؛ التنقل بلا تغييرات أبقى revision مشروع الاختبار عند 6.
- فتح مشروع آخر فارغ بدّل المحرر إلى Text ببرومبت فارغ وبدون مراجع المشروع السابق. لم يتم حفظ تعديلات في المشروع الفارغ.

- اختبارات الواجهة لا تثبت جودة فيديو جديد أو كل حالات الشبكة والأجهزة. قفل تعديل إعدادات المهمة الجاري تنفيذها يبقى منفصلًا عن تصفح النتائج.


## متابعة تنظيم Reuse وقائمة الإنتاج

- Reuse ينشئ مساحة مستقلة كاملة داخل فولدر مرتبط بمعرّف المشروع الأصلي. Reuse لنتيجة داخل نسخة Reuse يستمر تحت نفس الأصل. تغيير مسودة مشروع عادي ببيانات مشروع آخر لا يغير أصل الفولدر.
- نشر المساحة يتم مرة واحدة بعد تجهيز المسودة والمراجع. معرّف الطلب في الرابط يحدد مساحة واحدة؛ إعادة المحاولة لا تنشئ مشروعًا ثانيًا ولا تعيد كتابة التعديلات اللاحقة.
- عرض All يجمع النسخ داخل بطاقات Reuse؛ المشروع الأصلي يعرض اختصار Reuse مع العدد. البحث يعرض النسخ الفردية، وداخل الفولدر يوجد رجوع واضح إلى All projects.
- جُمعت ثلاث نسخ قديمة ذات مصدر مسجل واسم الإنشاء التلقائي داخل Reuse · Test Final وReuse · ASAS. لم تُستنتج علاقة للمشروع المسمى Reused shot من اسمه وحده. النقل اليدوي إلى أي فولدر يظل محفوظًا.
- New project وCreate project يستخدمان مسارًا واحدًا: حفظ الإعداد الحالي ثم محرر نظيف بإعدادات افتراضية ومراجع وLoRAs فارغة. المشروع العادي الجديد لا يرث فولدر Reuse المختار في المكتبة.
- Save setup محمي من التكرار والتبديل أثناء الحفظ. Export project ZIP تحت Project tools يحفظ المدخلات الحالية قبل التنزيل، بدون نافذة منبثقة غير مضمونة.
- غادِر المشهد الفارغ بدون التعطل في طلب حفظ لقطة غير موجودة؛ تبقى نقطة الحفظ المحلية. الحفظ والتصدير الصريحان يطلبان إنشاء/اختيار لقطة بدل الادعاء بأن مدخلاتها حُفظت على السيرفر.
- أزيلت روابط New واختيار المشروع المكررة ونافذة Reuse القديمة غير المستخدمة. بطاقة تجميع الفيديو لا تظهر عندما لا توجد لقطات مقبولة في النطاق الحالي، حتى مع وجود فيديوهات لمشاريع أخرى.
