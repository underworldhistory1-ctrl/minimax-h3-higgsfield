## الأدلة

- 225 اختبار JavaScript ناجحًا، مع مراجعة مستقلة للكود. تشمل اختبارات جديدة عزل الأسماء، تحديث الصفحة، حفظ المسودة، حدود الكاش، إعادة المحاولة، ترتيب المدخلات، وتنظيف الاستعادة المتأخرة. اختبارات Open أثناء الانشغال تتحقق من بقاء المهمة ومدخلاتها، ومن اختيار سيرفر صحيح حتى عندما يختلف عنوان الواجهة عن API وتوجد إعدادات قديمة لسيرفر آخر.
- API داخل السيرفر: قائمة المشاريع 15 ms تقريبًا، مشروع الاختبار 3 ms، مشروع ASAS ذو 34 لقطة 479 ms وحجم JSON نحو 1,298,603 بايت. الأرقام لقطة قياس واحدة وليست ضمانًا.
- تنزيل صورتين من الرابط العام، بإجمالي 10,081,761 بايت: أول وصول 3,637 ms وأربعة طلبات؛ التكرار داخل نفس controller نحو 0.12 ms وبدون طلب شبكة. هذا قياس جلب الأصول، وليس قياس فتح المشروع كله.
- تحقق تطابق ملفات JavaScript الخمسة المنشورة مع المصدر عبر API المحلي والرابط العام. لا توجد نسخة gzip قديمة تقدم بدل المصدر.
- اختبار متصفح حي: Refresh يحفظ Projects ثم Elements؛ Open للمشروع الحالي يعرض Production مع المراجع؛ تغيير اسم المرجع ثم إعادته لا يغير أسماء الكتالوج؛ التنقل بلا تغييرات أبقى revision مشروع الاختبار عند 6.
- فتح مشروع آخر فارغ بدّل المحرر إلى Text ببرومبت فارغ وبدون مراجع المشروع السابق. لم يتم حفظ تعديلات في المشروع الفارغ.
- الرندر الجاري بقي في الطابور أثناء النشر؛ لم تحدث إعادة تشغيل أو إلغاء أو توليد تجريبي إضافي.

## حدود المراجعة

- ذاكرة التنزيل تخص controller الحالي؛ الملفات الكبيرة لا تبقى فيها، وتحديث الصفحة قد يحتاج تنزيلًا جديدًا.
- البيانات التاريخية للمشاريع الكبيرة ما زالت كبيرة؛ الإصلاح يقلل التكرار ولا يعيد كتابة تاريخ اللقطات أو مصغراته.
- تعديل مشروع في جهاز آخر يمكن أن يسبب تعارض revision حقيقيًا؛ لا يتم تجاوز حماية البيانات أو إسقاط المراجع المفقودة.
- المراجع المضافة سابقًا لا تُحذف بالتخمين، لأن نفس الأصل قد يُستخدم عمدًا بأدوار أو أسماء مختلفة.
- اختبارات الواجهة لا تثبت جودة فيديو جديد أو كل حالات الشبكة والأجهزة. قفل تعديل إعدادات المهمة الجاري تنفيذها يبقى منفصلًا عن تصفح النتائج.
