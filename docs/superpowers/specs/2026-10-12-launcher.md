# Approved automatic H3 launcher

User approved the complete design in chat on 2026-10-12. No server access was supplied; implementation and simulated installation testing are authorized. Existing remote data must remain untouched.

One entry point for Windows/Linux. Detect installed ComfyUI and its actual interpreter; ambiguous installations require an explicit path. Reuse verified attached storage models, download only missing/invalid artifacts sequentially, resume interrupted downloads, preserve invalid targets in quarantine. Default video setup has Original, MotionCache, Spectrum, Realism People, Combat V2 and Motion Repair V2; Turbo is opt-in, never deleted. Full default includes Qwen INT8, Refine, ControlNet and CPU preprocessors, with opt-out profiles.

The launcher owns a process lock, versioned atomic state/report, bounded retries, progress log and reproducible configuration. It may not treat unknown queue status as empty, terminate a foreign server process, replace user-edited source, or expose unauthenticated public service. Wait for active jobs before changing runtime. Reuse valid files regardless of cached stage status. Resume must recheck artifacts and server; completed stages cannot conceal drift.

Prepared files, API readiness, and validated video/audio are separate statuses. Default end-to-end installation submits one short FL2VA smoke graph, persists its prompt ID before waiting, downloads its completed MP4 to the state directory, and validates it with the existing video/audio validator. A retry follows that prompt ID rather than resubmitting a costly generation. Timeout never cancels or duplicates jobs. No GPU quality claim without a real run.

Provider authentication, unsupported drivers, missing permissions, and modified installations can require action; report a precise recovery message without saving credentials. Install pinned compatible dependencies, never arbitrarily upgrade to latest. Reports must redact passwords/tokens and contain no private user prompts.
