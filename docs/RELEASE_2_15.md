# 2.15.0 - Named elements, fresh project tabs and storage

Released 4 November 2026. Model/runtime pins are unchanged.

- Project-element uploads require explicit names before uploading. Normalized current @mentions must be unique. The live catalog exposes current named mentions, without filename or previous-name synonyms. Direct shot uploads reserve only active reference aliases, preventing renamed catalog filenames from hijacking new references. Stored asset identities and historical take bindings remain intact.
- Remove is visible beside existing Replace controls. Project removal hides the reusable catalog entry; its media remains available to saved shots, results and exports. Shot-reference Remove detaches that card. Reference actions have a separate row; catalog actions use a compact grid.
- A fresh project tab starts with empty prompts, references, frames, guides and continuation. It inherits generation mode, canvas, LoRAs, sampling, Dials, refinement and other independent controls from that project's latest completed take with a stored draft. Soundtrack-source bindings and ControlNet inputs are not copied. Existing tab drafts and explicit Reuse retain their full setup. Other/new projects do not inherit these controls.
- Storage in both page headers reports real free/total bytes on the server output filesystem, without exposing paths. It does not count model disks separately. Updates run once per minute while visible, with bounded requests and no recursive scans.
- Clarify base checkpoints versus managed Pika Turbo adapters. [Pika Turbo](https://huggingface.co/Pika-Labs/Pika-H3-Flex-Turbo-LoRA) is distributed as LoRAs for compatible H3 bases. [Singularity v2](https://huggingface.co/WarmBloodAban/Minimax-h3_Singularity) is a replacement checkpoint; its approximately 5,000-character guidance is an upper-range recommendation, not a minimum. Creative adapters remain optional; supported Pika combinations retain automatic sampling.

Verification: 609 Python tests (608 pass, one platform skip), 327 JavaScript tests, existing 528-case plus 2,096-case graph matrices, and actual local browser/API journeys with simulated inference. The new journey checks required naming, filename isolation, visible Replace/Remove, persistent catalog removal, empty-input fresh tabs, settings inheritance, refresh retention, project isolation and live storage. Existing core and selection/recovery browser journeys also pass.

The launcher continues to follow official main, validate pinned artifacts and reuse verified shared files. No machine-specific credentials or paths were added. ComfyUI stays pinned to 0.43.0 pending GPU validation of 0.44.0. No new GPU render, measured GPU speedup, arbitrary-hardware guarantee or universal error-free claim is established.
